# Protected Modules

Protected modules require extra analysis before changes because defects can compromise authentication, authorization, data integrity, deployment, or system-wide behavior.

## Protected Areas

| Area | Files/Paths | Why Protected |
| --- | --- | --- |
| Authentication/session | future login/logout/register/reset servlets, `RoleSelectionServlet`, auth/session JSPs | Controls user identity, session entry/exit, and role context |
| Authorization | `RolePermissionUtil`, role session attributes, protected route mappings | Controls access to management/POS behavior |
| Database connection | `DatabaseUtil`, `web.xml` DB context params | Affects every DAO and all persistence behavior |
| Database schema | `sql/*.sql` | Affects data integrity and DAO compatibility |
| Payment/finance | `Payments`, `FinanceTransaction`, `Orders`, future payment modules | Financial correctness and auditability |
| Build/deploy config | `build.xml`, `nbproject/project.properties`, `web/META-INF/context.xml`, `web/WEB-INF/web.xml` | Affects compile, packaging, runtime compatibility, and deployment |
| Generated outputs | `build/`, `dist/` | Must not be hand-edited because they are regenerated by Ant/NetBeans |

## Change Checklist

Before modifying protected modules:

1. Read all directly related files.
2. Identify route mappings and servlet/listener configuration.
3. Identify session attributes and JSP dependencies.
4. Identify database tables and columns affected.
5. Identify build/deploy compatibility risks for Tomcat 10.1 and NetBeans Ant.
6. Identify rollback and compatibility risks.
7. Make the minimal change.
8. Run `ant clean dist` or a documented fallback verification.
9. Update relevant docs.

## Current Protected Risks

- Database credentials exist in source/config and must be externalized before production use.
- Password/authentication behavior is not production-hardened.
- Session cookie security depends on local/prod deployment settings.
- Ant is not currently available in PATH in the observed local shell, so NetBeans or manual Ant setup may be required for full WAR builds.
